# Introduction:

This was a class project to build a messaging application, both the server-side and client-side applications. Demonstrating the use of socket programming and javafx services and threads.

You can register users onto the database and the application has basic features like chat messaging (with messages being stored on a sql database) and online indicators and a fun little "prod" function.

It is designed to operate in conjunction with a sql database. I have built the application with the intention that communication between the server and client applications are encrypted using a shared key, 
but again the data in the database is NOT encrypted at all (Like I said, please don't use this for any actual communication).

# Requirements:

JavaFX (I used SDK 19)

# How to run:

This is a JavaFX program. I ran it using Eclipse IDE, alongside XAMPP for the MySQL database.

The server side application should be started by running "ServerUI.java" The client side application should be started by running "ClientUI.java"

Add your JavaFX user library build path (Right click on the project -> Build Path -> Add Library), and add the VM arguments to the ServerUI.java and ClientUI.java files.
For the tests add "JUnit 5" to the project's classpath as well. 

Instructions for how to create a JavaFX user library and how to setup the VM arguments can be found on https://openjfx.io/openjfx-docs/#install-javafx in the JavaFX and Eclipse -> Non-modular from IDE section.

In this demo, the AES encryption key is a key generated by "OneOffKeygen.java" which both the client and server share for communication between each other.

If deploying the server side application on a remote VM as a runnable .jar file, then update the aes key filepath accordingly.

I've included a demo database (demoMsgDatabase.sql), so create a database with the same name and import it. It has some demo users ("aliceon" and "bobward", the password is "abcd" for both of them) in there and you can of course make your own users.
- In Server.java on line 105 and 106, set your localhost username and password accordingly
